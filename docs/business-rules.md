# 业务规则

## 通用规则

- 金额统一用 Decimal 计算，数据库字段使用 `NUMERIC`，禁止使用 float。
- 数量支持小数，库存、送货数量、收货数量均使用 `NUMERIC(18,4)`。
- 销售单、采购单、库存流水、资金流水必须在同一个数据库事务中提交。
- 所有库存变化必须生成库存流水，不允许直接覆盖库存数量。
- 所有资金变化必须生成资金流水，不允许直接覆盖账户余额。
- 草稿不影响库存、资金、应收应付和报表。
- 已确认单据原则上不允许直接改核心金额和数量，如需更正，优先作废后重开。
- 作废不物理删除原单据，状态改为 `voided`，并生成反冲流水。

## 销售单草稿、确认、作废规则

- 草稿：
  - 可保存客户、日期、地址、产品明细、收款明细、备注和附件。
  - 不扣减库存，不生成资金流水，不计入客户应收，不进入经营报表。
  - 草稿可继续编辑、删除或确认。
- 确认：
  - 必须选择有效客户。
  - 至少有一条产品明细或非产品费用金额大于 0。
  - 明细数量必须大于 0，单价不能小于 0。
  - 优惠金额不能小于 0，且不能使合同金额小于 0。
  - 确认后计算合同金额、已送货金额、已收款、未收款、送货状态、收款状态。
  - 如有送货数量，必须同步扣减库存并写库存流水。
  - 如有收款金额或预收款冲销，必须生成资金流水或预收冲销记录。
- 作废：
  - 只能作废已确认单据。
  - 已作废单据不能再次作废。
  - 作废必须填写原因。
  - 作废后生成反向库存流水和反向资金流水。
  - 作废后客户应收、已收款、未收款统计按反冲后的结果重新计算。

## 销售送货与库存扣减规则

- 销售明细中的 `delivered_quantity` 表示本单已送货数量。
- `delivered_quantity` 不能小于 0，不能大于销售数量。
- 确认销售单时，送货数量大于 0 的明细生成库存出库流水。
- 出库数量按产品规格扣减 `inventory_balances.quantity`。
- 第一版建议默认禁止负库存；如果后续开放负库存，需要系统设置明确开启。
- 库存流水记录出库前数量、出库数量、出库后数量、来源销售单号和来源明细。
- 送货状态：
  - 全部明细送货数量为 0：未送货。
  - 存在送货数量但未全部送完：部分送货。
  - 所有明细送货数量等于销售数量：全部送货。

## 销售收款与客户应收规则

- 销售单合同金额 = 产品金额 + 非产品费用 - 优惠金额，可按税率扩展税额。
- 客户应收增加 = 销售单合同金额。
- 已收款 = 销售单收款流水金额 + 使用预收款冲销金额。
- 未收款 = 合同金额 - 已收款，允许为负数，负数代表超收或形成预收。
- 收款流水必须关联资金账户，确认后增加账户余额。
- 收款状态：
  - 已收款为 0：未收款。
  - 已收款大于 0 且小于合同金额：部分收款。
  - 已收款等于合同金额：全部收款。
  - 已收款大于合同金额：超收款。
- 客户列表汇总：
  - 合同金额统计已确认且未作废销售单合同金额。
  - 已送货统计已确认且未作废销售单已送货金额。
  - 已收款统计销售收款流水和预收款冲销。
  - 未收款统计期初应收 + 合同金额 - 已收款。

## 采购单草稿、确认、作废规则

- 草稿：
  - 可保存供应商、日期、地址、产品明细、付款明细、备注和附件。
  - 不增加库存，不生成资金流水，不计入供应商应付，不进入经营报表。
- 确认：
  - 必须选择有效供应商。
  - 至少有一条产品明细或非产品费用金额大于 0。
  - 明细数量必须大于 0，单价不能小于 0。
  - 优惠金额不能小于 0，且不能使合同金额小于 0。
  - 如有收货数量，必须同步增加库存并写库存流水。
  - 如有付款金额或预付款冲销，必须生成资金流水或预付冲销记录。
- 作废：
  - 只能作废已确认采购单。
  - 作废必须填写原因。
  - 作废后生成反向库存流水和反向资金流水。
  - 作废后供应商应付、已付款、未付款统计按反冲后的结果重新计算。

## 采购收货与库存增加规则

- 采购明细中的 `received_quantity` 表示本单已收货数量。
- `received_quantity` 不能小于 0，不能大于采购数量。
- 确认采购单时，收货数量大于 0 的明细生成库存入库流水。
- 入库数量按产品规格增加 `inventory_balances.quantity`。
- 成本均价按移动加权平均计算：
  - 新成本均价 = `(原库存数量 * 原成本均价 + 本次入库数量 * 本次单价) / (原库存数量 + 本次入库数量)`。
  - 原库存数量小于等于 0 时，可直接采用本次入库单价作为成本均价。
- 收货状态：
  - 全部明细收货数量为 0：未收货。
  - 存在收货数量但未全部收完：部分收货。
  - 所有明细收货数量等于采购数量：全部收货。

## 采购付款与供应商应付规则

- 采购单合同金额 = 产品金额 + 非产品费用 - 优惠金额，可按税率扩展税额。
- 供应商应付增加 = 采购单合同金额。
- 已付款 = 采购单付款流水金额 + 使用预付款冲销金额。
- 未付款 = 合同金额 - 已付款，允许为负数，负数代表超付款或形成预付款。
- 付款流水必须关联资金账户，确认后减少账户余额。
- 付款状态：
  - 已付款为 0：未付款。
  - 已付款大于 0 且小于合同金额：部分付款。
  - 已付款等于合同金额：全部付款。
  - 已付款大于合同金额：超付款。
- 供应商列表汇总：
  - 合同金额统计已确认且未作废采购单合同金额。
  - 已收货统计已确认且未作废采购单已收货金额。
  - 已付款统计采购付款流水和预付款冲销。
  - 未付款统计期初应付 + 合同金额 - 已付款。

## 库存期初、调整、流水规则

- 产品新建或库存初始化时可录入期初库存。
- 期初库存保存后生成 `source_type = opening` 的入库流水。
- 盘点时录入盘点数量，系统计算差异数量：
  - 差异数量 > 0：生成调整入库流水。
  - 差异数量 < 0：生成调整出库流水。
  - 差异数量 = 0：不生成流水，可记录盘点日志。
- 手工调整必须填写原因。
- 库存流水一旦生成原则上不可编辑和删除，只能通过反向调整纠正。
- 库存列表的当前数量必须由 `inventory_balances` 提供，`inventory_balances` 只能由库存服务在事务中更新。

## 订单作废后的库存和资金反冲规则

- 销售单作废：
  - 对每条销售出库流水生成相同数量的反向入库流水。
  - 对每条销售收款资金流水生成相同金额的反向支出流水。
  - 对预收款冲销恢复客户预收余额。
- 采购单作废：
  - 对每条采购入库流水生成相同数量的反向出库流水。
  - 对每条采购付款资金流水生成相同金额的反向收入流水。
  - 对预付款冲销恢复供应商预付余额。
- 费用收入作废：
  - 收入作废生成反向支出流水。
  - 费用作废生成反向收入流水。
- 反冲流水必须关联原流水，便于审计。
- 作废反冲必须和单据状态更新在同一个事务中完成。

## 报表统计口径

- 默认只统计已确认且未作废的销售单、采购单、费用收入和资金流水。
- 草稿不进入报表。
- 销售流水按销售日期统计销售金额、成本、毛利、收款状态。
- 采购流水按采购日期统计采购金额、付款状态、收货状态。
- 产品销售总览按产品或规格汇总销售数量、销售金额、销售占比、毛利。
- 送货提醒表按计划送货日期和未送货数量统计。
- 收货提醒表按计划收货日期和未收货数量统计。
- 销售欠款汇总按客户统计期初应收、销售应收、已收款、未收款。
- 采购付款汇总按供应商统计期初应付、采购应付、已付款、未付款。
- 资金流水表按发生日期统计资金收入和支出。
- 净利润报表可按销售毛利 + 其他收入 - 费用支出统计，采购成本按销售出库时的成本均价取数。

## 打印字段配置规则

- 打印配置按打印对象类型保存，销售单和采购单可分别配置。
- 可配置字段包括金额、合计金额、收付款记录、送货/收货数量、非产品费用、条形码、累计欠款、上期欠款、附件、条款、打印时间、相同产品合并、产品合计、图片、规格、备注、页码、二维码等。
- 打印字段为空时，若启用“无值不打印”，则隐藏该字段。
- 打印时应生成打印快照，保证已打印单据后续可追溯。
- 打印模板不得复用参考资料 HTML/CSS，需用本系统独立实现。

## 数据备份规则

- 管理员可手动创建备份。
- 备份内容至少包含 SQLite 数据库文件和附件目录索引。
- 备份文件命名建议包含日期时间，如 `backup_YYYYMMDD_HHmmss.db`。
- 恢复数据前必须：
  - 提示恢复会覆盖当前数据。
  - 自动生成恢复前备份。
  - 校验备份文件存在且格式有效。
- 恢复操作必须记录操作日志。
- 备份失败必须记录错误信息，不能静默失败。
